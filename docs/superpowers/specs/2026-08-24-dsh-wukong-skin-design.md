## 1. 核心叙事：你执笔，大圣执棍

用户是天命人，下达意志；悟空是化身，替用户降妖。每个任务是一场「降妖」，
每个工具调用是一记棍招。悟空五态立绘常驻右侧角色轨道，是可见的 agent 伙伴
（否决概念稿「强角色只出现在 New Session」的克制路线——用户已确认）。

概念稿保留的部分：全屏横版封面 + 「直面天命」hero 的 New Session、
墨黑/古铜/暗金/余烬 token 系统、克制的工作态排版、
会话列表的 战/眼/棍/甲/经 单字图标。

## 2. 诚实状态机：五态合同

继承 afterglow 验证过的 DOM 证据合同，全新实现。所有状态来自产品真实
DOM 信号，不伪造任何进度。

| 状态 | 命名 | DSH 真实信号 | 呈现 |
|---|---|---|---|
| Dialogue | 问道 | 空闲对话 | 盘坐/拄棍待机立绘，冷月青灰场景，安静水墨 |
| Choice | 岔路 | `[data-question-key]` / `[data-plan-review-key]` / `[data-approval-key]` | 场景退暗，选项变成编号「签文/岔路」卡，悟空抱棍侧目望向选项 |
| Execution | 降妖 | `[data-chat-flow]` 内工具行 `data-state='running'` 或回合状态行 `[role='status']` | 挥棍姿态，场景光转余烬色，顶部战斗 HUD |
| Recovery | 受创 | 工具行翻转为 `data-state='error'`（仅当前回合新增） | 单膝受击立绘，一次性金甲碎裂 + 短震动，错误信息保持可读 |
| Clear | 功成 | 战斗态自然结束且无新错误 | 立棍收势，金箍光环一次性扩散后回落 |

状态正确性硬规则（沿用 afterglow 验收标准）：

- 打开含历史错误的旧会话不触发受创：初始化时建立历史错误计数基线，仅响应当前回合新增错误。
- 当前新失败只触发一次受创；受创期间 HUD、角色、名牌为同一状态，不出现「降妖」与「受创」同屏冲突。
- 普通回合结束不叫「功成」；无权威分母时不显示 Boss 血条、百分比或任何虚构完成度。

## 3. 黑神话专属交互系统（差异化核心）

把黑神话的真实游戏机制映射到 DSH 的真实产品信号上：

- **棍势连击条**：当前回合内每个真实成功的工具行积一颗棍势珠（上限 4 颗），
  出错清零。这是 afterglow「行动链菱形」的换代——连击/清零规则让成功链条有
  积累感、失败有代价感。数据源只有真实工具行状态。
- **棍势三式 = reasoning effort**：戳棍势（low）/ 立棍势（medium）/
  劈棍势（high）。切换走产品原生菜单，呈现为架势切换 + 悟空持棍姿势微调。
- **披挂 = 模型选择**：模型选择器呈现为「披挂」装备槽（如意金箍棒槽位），
  选项从产品原生菜单动态读取，不写死模型名，不生成虚假可用状态。
- **定身术 = 停止**：用户点 Stop 时播一次性金色定身圈动画，HUD 冻结定格。
- **章回体 = todo/plan**：todo 面板呈现为回目列表（「第一回 · 修复登录测试」），
  pending/in-progress/completed = 未点灯/燃灯/灯灭结回。仅真实 todo 存在时显示。
- **影神图 = Trajectory**：轨迹页皮肤化为影神图卷轴，每条 run 事件配
  木刻风徽记（按工具名正则映射，复用 afterglow 的 emblem 规则思路）。
- **水墨转场**：五态切换用一次性水墨晕染擦除。
- **土地庙 = New Session**：全屏封面页即土地庙——焚香（composer）起行。

刻意不做：Boss 血条、假百分比、全屏「死」字、永久粒子/呼吸/扫光循环、
七十二变→子 agent 分身（DOM 信号不够稳定，列为远期观察项）。

## 4. 视觉系统

### 4.1 Token（取自概念稿）

| Token | 值 | 用途 |
|---|---|---|
| Void | `#080706` | 底色 |
| Armor Ink | `#171411` | Surface |
| Old Gold | `#B9813F` | 主强调（另有亮金 `#E0B167`） |

比例约 72% 墨黑 / 14% 暗褐 Surface / 8% 古金 / 3% 青铜 / 2% 余烬橙 / 1% 危险红（`#AD3E33`）。
辅助色：玉青 `#7D9A87` 用于验证成功/落定态。

### 4.2 场景

黑风山云海古刹背景：问道态（冷月青灰光照）与降妖态（火烧云余烬光照）
同构图两版 + 雾层 + 执行光效遮罩，分层出图。不预先重度模糊；
运行时对局部面板用 backdrop blur（afterglow 5.1 经验）。

### 4.3 角色

五态主立绘：盘坐问道 / 抱棍岔路 / 挥棍降妖 / 单膝受创 / 立棍功成。

- 剪影差异优先于表情差异；五态统一比例、光向、服装、透视、落点。
- 主图高 ≥1600px 透明 PNG + 800–1000px 胸像裁切；透明边缘无色边残块。
- AI 生成黑神话风格原创绘制（风格致敬，不扒游戏素材）；概念稿封面图直接用于 New Session。

### 4.4 响应式（照搬 afterglow 四档）

| 视口 | 角色 | 场景处理 |
|---|---|---|
| ≥1440px | 全身立绘 | 完整三栏舞台，右侧固定角色轨道 |
| 1024–1439px | 半身 | 窄角色轨道 |
| 768–1023px | 胸像 | 角色靠近名牌；HUD 折叠 |
| <768px | 名牌头像 | 保留角色身份，不完全隐藏 |

角色安全区：任何消息卡、弹窗、composer 不得覆盖脸部与主要手势。

### 4.5 明暗

暗色为唯一主版本。亮色「经卷宣纸版」列为可选后期项，P0–P3 不做。

## 5. 工程架构

新仓库 `~/Workspace/deepseek/dsh-wukong`。插件合同与 afterglow 一致：
`skin.json`（id `wukong`，package `@dsh-external/dsh-wukong`，bodyAttr
`data-dsh-wukong`）+ Cordis 插件 + effect disposer 完整还原全部 CSS/DOM 写入。

修正 afterglow 单文件 1020 行的结构债，按职责拆分：

```
src/client/
  contract.ts      # DOM 选择器合同 + 状态机推导（唯一读产品 DOM 的地方）
  stage.ts         # 角色舞台（五态立绘、响应式档位）
  hud.ts           # 战斗 HUD + 棍势连击条
  choice.ts        # 岔路选择接管
  loadout.ts       # 披挂/棍势三式（代理原生菜单）
  vfx.ts           # 一次性特效（水墨转场/定身/碎甲/金箍）
  chapters.ts      # 章回 todo + 影神图 trajectory
  art.generated.ts # 内嵌资产（assets-gen 管线生成）
  wukong.module.css
```

每个模块只依赖 `contract.ts` 输出的状态，不各自摸 DOM。

交互红线（继承 afterglow）：

- 克隆元素不做真实提交入口；发送、选择、审批、模型/effort 切换全部走原生控件或受支持 slot。
- Scene Layer 失败时用户可回退到完整原生交互；不删除、截断、改写原始消息。
- 所有交互可用键盘完成。
- `prefers-reduced-motion` 下移除斩线、震动、视差、粒子，只保留颜色/形状/标签变化。

## 8. 验收标准

### 8.1 视觉

- 隐藏所有状态文字后，测试者仍能识别问道、岔路、降妖、受创四态。
- 1600×900 与 1280×720 下，任何卡片不覆盖悟空的脸或主要手势。
- 五张角色资产连续切换时头部、肩宽、落点稳定。

### 8.2 状态

- 打开含历史失败的旧会话不触发受创；当前新失败只触发一次。
- 受创时不存在「降妖」与「受创」同屏冲突。
- 无 plan/todo 时不显示章回面板；普通回合结束不触发功成。
- 棍势珠数量恒等于当前回合真实成功工具行数（上限 4），出错后归零。

### 8.3 交互

- 原生发送、选择、审批、模型、effort、权限操作全部可用；皮肤层失败可回退原生。
- 所有交互可用键盘完成；reduced-motion 下无循环扫描、震动、视差。
- 卸载/停用后 DOM 与样式完整还原（disposer 验证）。
